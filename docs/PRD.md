# 잇다 — PRD

## 1. 프로젝트 개요

분실물과 습득물 정보를 매칭해 분실물을 찾을 수 있도록 돕는 서비스.

- **개발 인원:** 2명
- **개발 기간:** 약 1~2개월
- **대상 지역:** 서울
- **플랫폼:** 모바일 애플리케이션

## 2. 프로젝트 목적

분실자와 습득자를 연결하여 분실물 탐색부터 실제 반환까지의 과정을 편리하게 만드는 것을 목적으로 한다.

**해결하고자 하는 문제**

- 분실물·습득물 정보를 체계적으로 등록하고 관리하기 어렵다.
- 관련 게시글을 직접 비교해야 하므로 물건을 찾는 데 시간이 걸린다.
- 장소와 날짜가 비슷한 게시글을 발견하기 어렵다.

**핵심 가치**

- 관련 게시글을 자동으로 추천한다.
- 게시글을 통해 분실자와 습득자가 직접 소통할 수 있도록 지원한다.
- 실제 반환 결과를 기록하고 관련 게시글의 상태를 관리한다.

## 3. 주요 사용자

하나의 계정으로 두 역할을 모두 수행할 수 있다.

### 3.1 분실자

- 분실물 등록 및 관련 습득물 탐색·매칭 후보 확인
- 습득자와 소통하여 소유 여부 확인 및 반환 협의
- 반환 기록 및 상대 정보 확인, 정책에 따른 반환 기록 취소

### 3.2 습득자

- 습득물 등록 및 관련 분실물 탐색·매칭 후보 확인
- 분실자와 소통하여 소유 여부 확인 및 반환 협의
- 반환 완료 후 반환 처리

## 4. 핵심 기능 요구사항

### 4.1 회원가입 및 로그인

- 이메일, 비밀번호, 닉네임으로 회원가입한다.
- 로그인 및 로그아웃을 지원한다.
- 회원가입과 로그인을 제외한 모든 서비스 기능은 로그인 사용자만 이용할 수 있다.

### 4.2 게시글 관리

분실물 또는 습득물 게시글을 등록·수정·삭제하고 목록과 상세 정보를 조회할 수 있다.

**입력 항목**

- 게시글 유형: `분실물`, `습득물`
- 카테고리
- 물건명
- 분실일 또는 습득일
- 장소
- 이미지 (선택, 최대 5장)
- 특징 (선택)

**요구사항**

- 작성자는 본인이 등록한 게시글을 관리할 수 있다.
- 이미지를 첨부하지 않아도 게시글을 등록할 수 있다.
- 게시글 상태는 `4.6`의 상태 관리 규칙에 따라 변경한다.
- 게시글 이미지의 파일 형식과 크기를 제한한다.
- 이미지 업로드 실패 시 작성자가 실패 사실을 확인하고 재시도할 수 있어야 한다.
- 반환 완료 상태의 게시글은 수정 및 삭제할 수 없다. 반환 기록이 취소되어 게시글 상태가 복구된 경우에는 일반적인 규칙을 적용한다.

### 4.3 게시글 검색 및 필터링

다음 조건으로 게시글을 검색하고 필터링한다.

- 게시글 상태
- 카테고리
- 키워드
- 날짜
- 장소

**요구사항**

- 검색 조건에 맞는 게시글 목록을 제공한다.
- `반환 완료` 상태의 게시글도 일반 게시글 목록에서 조회할 수 있다.
- 검색 결과가 없는 경우 사용자에게 안내한다.

### 4.4 게시글 매칭

규칙 기반 점수화를 통해 관련성이 높은 분실물·습득물 게시글을 매칭 후보로 제공한다.

**비교 기준**

- 카테고리
- 분실일과 습득일의 차이
- 장소의 일치 또는 근접성
- 특징의 키워드 유사성

**요구사항**

- 분실물은 습득물, 습득물은 분실물과 매칭한다.
- 본인이 작성한 게시글은 후보에서 제외한다.
- `찾는 중` 상태의 분실물과 `보관 중` 상태의 습득물만 신규 매칭 후보로 제공한다.
- 반환 완료 상태의 게시글은 신규 매칭 후보에서 제외한다.
- 매칭은 실제 소유자를 확정하는 판정이 아니라 확인이 필요한 후보를 추천하는 기능이다.
- 매칭 후보의 게시글 상태가 변경되었으면 최신 상태를 확인하고 유효하지 않은 후보에 대한 진행을 제한한다.
- 본인이 작성한 게시글의 상세 화면에서 관련된 매칭 후보 목록을 확인할 수 있다.
- 매칭 후보별 관련성 점수를 확인할 수 있다.
- 매칭 후보를 선택하면 해당 게시글의 상세 정보를 조회할 수 있다.

점수 배점과 후보 선정 기준은 `MATCHING.md`에서 정의한다.

### 4.5 채팅 관리

**채팅방**

- 매칭 후보에서 대화를 시작할 때는 두 게시글이 각각 `찾는 중`과 `보관 중` 상태인지 확인한다.
- 게시글 상세 화면에서 해당 게시글 작성자와 대화를 시작할 수 있다. 대화를 시작하는 사용자에게 대응하는 반대 유형 게시글이 없어도 된다.
- 본인이 작성한 게시글에서는 대화를 시작할 수 없다.
- 채팅방에는 두 명의 사용자만 참여한다.
- 채팅방은 참여자 쌍과 관련 게시글을 기준으로 식별한다.
- 양쪽 게시글이 연결된 경우, 두 게시글의 조합과 참여자 쌍을 기준으로 기존 채팅방을 재사용한다.
- 한쪽 게시글만 연결된 경우, 해당 게시글과 참여자 쌍을 기준으로 기존 채팅방을 재사용한다.
- 반환 완료된 게시글에 실제 반환 상대 게시글이 연결되어 있으면 해당 게시글을 확인할 수 있다.
- 채팅 목록은 마지막 메시지 시각을 기준으로 최신순 정렬한다.
- 각 채팅방에는 마지막 메시지의 내용 일부와 마지막 메시지 시각을 표시한다.

**메시지**

- 텍스트 메시지를 전송하고 기존 메시지 내역을 조회할 수 있다.
- 이미지 첨부 메시지를 지원한다.
- 채팅 참여자만 해당 채팅방과 메시지에 접근할 수 있도록 서버에서 권한을 확인한다.
- 채팅 이미지는 권한이 있는 사용자만 조회할 수 있도록 처리한다.
- 사용자는 비공개 물건 특징 등을 활용해 소유 여부를 확인하고 반환 방법을 협의한다.
- 반환 완료 처리 또는 반환 기록 취소 후에도 기존 채팅방과 메시지 내역을 조회할 수 있다.
- 메시지 저장과 이미지 업로드는 실패 상황을 구분해 처리한다.

**메시지 푸시 알림**

- 새 채팅 메시지가 도착하면 FCM을 이용해 상대방에게 푸시 알림을 전송한다.
- 푸시 알림을 선택하면 해당 채팅방으로 이동할 수 있어야 한다.
- 푸시 알림 전송은 메시지 저장과 별도로 처리한다. 푸시 알림 전송에 실패하더라도 저장된 메시지를 실패한 것으로 처리하지 않는다.
- 유효하지 않은 기기 토큰은 정리하거나 갱신할 수 있도록 관리한다.
- 반환 완료 및 반환 기록 취소 안내는 채팅 메시지로 전달한다. 별도의 반환 전용 푸시 알림 유형은 두지 않는다.

MVP에서는 메시지 저장·전송·조회, 이미지 첨부, 메시지 푸시 알림을 구현한다. WebSocket 기반 실시간 채팅과 읽음 표시는 후순위 기능이다.

### 4.6 게시글 상태 및 반환 기록 관리

#### 4.6.1 게시글 상태

| 게시글 유형 | 반환 전 상태 | 반환 후 상태 |
|---|---|---|
| 분실물 | 찾는 중 | 반환 완료 |
| 습득물 | 보관 중 | 반환 완료 |

**게시글 상태 관리**

- `반환 완료` 상태는 유효한 반환 기록을 기준으로 관리한다.
- 매칭 후보가 발견되거나 대화를 시작했다는 이유만으로 게시글 상태를 변경하거나 반환 기록을 생성하지 않는다.
- 반환 기록이 취소되면 해당 반환 기록과 연결된 게시글 중 실제 존재하고 상태 복구가 가능한 게시글만 반환 전 상태로 복구한다.

#### 4.6.2 반환 완료 처리

- 실제 반환을 진행한 습득자가 채팅방에서 반환 완료를 처리한다.
- 서버는 처리 요청자의 채팅 참여 여부와 습득자 역할, 반환 기록의 생성 가능 여부, 연결할 게시글의 유형 및 최신 상태를 검증한다.
- 반환 완료 처리 시 반환 기록을 생성한다.
- 반환 기록에는 실제 분실자와 습득자의 사용자 정보를 기록한다.
- 양쪽 게시글이 존재하는 경우, 두 게시글의 반환 기록을 연결한다.
- 한쪽 게시글만 존재하는 경우에도 반환 기록을 생성할 수 있다. 이때 실제 반환 당사자의 사용자 정보와 확인 가능한 게시글 정보만 기록한다.
- 반환 완료 처리 후 반환 기록과 연결된 게시글은 `반환 완료` 상태로 변경한다.
- 반환 완료 처리에 실패하면 반환 기록과 관련 게시글 상태가 일부만 변경된 상태로 남지 않도록 한다.
- 반환 기록에 실제 반환 상대 게시글이 연결된 경우 해당 게시글을 확인할 수 있어야 한다.

#### 4.6.3 반환 기록 취소

- 반환 완료 처리 시점부터 7일 이내에는 해당 반환 기록의 분실자 역할 사용자만 취소할 수 있다.
- 서버는 요청자의 권한, 반환 기록의 유효 상태 및 취소 가능 기간을 검증한다.
- 반환 기록을 삭제하지 않고 취소 상태로 보존한다.
- 취소 시 실제로 연결되어 있는 분실물 게시글은 `찾는 중`으로, 습득물 게시글은 `보관 중`으로 복구한다.
- 연결된 게시글이 없는 경우 해당 게시글의 상태를 변경하지 않는다.
- 취소된 반환 기록은 현재 유효한 반환 완료 기록으로 표시하지 않는다.
- 반환 완료 후 7일이 지난 기록은 일반적인 취소 기능으로 취소할 수 없다.

#### 4.6.4 취소 이후 처리

- 취소된 반환 기록과 연결된 게시글은 상태 복구가 완료되면 다시 매칭 후보가 될 수 있다.
- 기존 채팅방, 메시지 및 반환 기록 이력을 보존한다.
- 취소 가능 여부는 클라이언트 시간이 아니라 서버의 검증 결과를 따른다.
- 반환 완료 또는 취소 요청이 중복으로 처리되지 않도록 한다.
- 반환 기록의 이력과 현재 유효한 반환 기록을 구분한다.
- 같은 당사자가 다시 반환을 진행하면 새로운 반환 기록을 생성한다.
- 새로운 반환 기록은 새 반환 완료 처리 시점과 실제 반환 당사자 정보를 기준으로 관리한다.

매칭 후보별 진행 상태와 채팅방별 업무 상태는 MVP에서 별도로 관리하지 않는다.

### 4.7 마이페이지

- 본인의 프로필 정보를 확인할 수 있다.
- 본인이 작성한 게시글 목록과 각 게시글의 현재 상태를 확인할 수 있다.
- 본인이 참여한 반환 기록과 실제 반환 상대 정보를 확인할 수 있다.
- 프로필 수정, 비밀번호 변경, 로그아웃 및 회원탈퇴를 할 수 있다.

## 5. 화면 구성

**주요 화면**

1. **홈:** 검색, 분실물·습득물 구분, 게시글 목록
2. **게시글 검색·필터:** 게시글 검색 및 조건별 탐색
3. **게시글 상세:** 물건 정보, 작성자 정보, 매칭 결과 확인, 작성자용 관리 기능, 채팅 시작
4. **게시글 등록·수정:** 분실물·습득물 정보 입력 및 이미지 첨부
5. **채팅 목록:** 참여 중인 채팅방 목록, 최신 메시지순 정렬, 최근 메시지 내용 일부 표시
6. **채팅방:** 1:1 채팅, 텍스트·이미지 메시지, 반환 완료 처리 및 반환 기록 취소
7. **마이페이지:** 프로필, 내 게시글·반환 기록, 프로필 수정·비밀번호 변경·로그아웃·회원탈퇴
8. **회원가입 및 로그인:** 계정 생성 및 인증
9. **프로필 수정:** 기존 프로필 정보 수정
10. **비밀번호 변경:** 기존 비밀번호 변경
11. **회원 탈퇴:** 탈퇴 안내 및 유의사항, 탈퇴 처리

세부 화면과 이동 흐름은 `SCREEN.md`에서 정의한다.

## 6. MVP 범위

### 6.1 필수 기능

- 회원가입 및 로그인
- 게시글 관리
- 이미지 업로드·조회 (게시글당 최대 5장)
- 게시글 검색 및 필터링
- 규칙 기반 게시글 매칭
- 텍스트·이미지 첨부를 지원하는 채팅
- 게시글 상태 및 반환 기록 관리
- 메시지 푸시 알림
- 마이페이지
- 백엔드·데이터베이스 배포 및 배포 환경 테스트

### 6.2 후순위 기능

- WebSocket 기반 실시간 채팅 및 읽음 표시

## 7. 기술 스택 및 시스템 구성

### 7.1 기술 스택

| 영역 | 기술 | 목적 |
|---|---|---|
| 프론트엔드 | Flutter, Dart | 모바일 앱 |
| 백엔드 | Java 21, Spring Boot | REST API 및 서비스 로직 |
| 데이터베이스 | PostgreSQL | 사용자·게시글·반환 기록·채팅 데이터 |
| 이미지 저장소 | Cloudinary | 게시글 및 채팅 이미지 저장·조회 |
| 푸시 알림 | Firebase Cloud Messaging | 메시지 푸시 알림 |
| CI | GitHub Actions | 자동 빌드 및 테스트 |
| 배포 | Render | 백엔드 배포 및 데이터베이스 연동 |
| 형상 관리 | Git, GitHub | 코드 관리 및 협업 |

### 7.2 시스템 구성

Flutter 앱은 REST API를 호출하고, Spring Boot 서버는 PostgreSQL을 통해 사용자·게시글·반환 기록·채팅 데이터를 관리한다.

**이미지 저장**

- 게시글 및 채팅 이미지는 Cloudinary에 저장한다.
- PostgreSQL에는 이미지 식별자, URL 등 필요한 메타데이터를 저장한다.
- 비밀 API 키를 Flutter 앱에 포함하지 않는다.

**푸시 알림**

- Flutter 앱은 FCM 수신에 필요한 기기 토큰을 관리한다.
- 기기 토큰의 저장·갱신·삭제 방식과 알림 전송 API는 세부 설계 문서에서 정의한다.

**배포**

- 배포 환경에서도 API 연동과 이미지 업로드·조회가 정상적으로 동작하도록 검증한다.

프로젝트 실행 방법과 구조는 `README.md`에서 관리한다.
