# 잇다 — PRD

## 1. 프로젝트 개요

분실물과 습득물 정보를 등록하고, 물건의 종류·장소·날짜·특징을 바탕으로 관련 게시글을 매칭해 반환을 돕는 모바일 서비스다.

- **프로젝트 유형:** 2인 팀 모바일 앱 프로젝트
- **개발 기간:** 약 1~2개월
- **대상 지역:** 서울
- **대상 사용자:** 서울에서 물건을 분실했거나 습득한 사람

## 2. 프로젝트 목적

분실자와 습득자를 연결하여 분실물 탐색과 반환 과정을 편리하게 만드는 것을 목적으로 한다.

**해결하고자 하는 문제**
- 분실물·습득물 정보를 체계적으로 등록하고 관리하기 어렵다.
- 관련 게시글을 직접 비교해야 하므로 물건을 찾는 데 시간이 걸린다.
- 장소와 날짜가 비슷한 게시글을 발견하기 어렵다.
- 게시글 정보만으로 실제 소유자를 확인하기 어렵다.

**핵심 가치**
- 관련 게시글을 자동으로 추천하고, 사용자 간 소통을 통해 실제 반환까지 이어지도록 지원한다.

## 3. 주요 사용자

### 3.1 분실자
- 분실물 게시글을 등록하고 관련 습득물 매칭 후보를 확인한다.
- 습득자와 대화하여 소유 여부를 확인한다.
- 물건을 찾으면 게시글 상태를 `찾음`으로 변경한다.

### 3.2 습득자
- 습득물 게시글을 등록하고 관련 분실물 매칭 후보를 확인한다.
- 분실자와 대화하여 소유 여부를 확인한다.
- 물건을 돌려주면 게시글 상태를 `반환 완료`로 변경한다.

하나의 계정으로 두 역할을 모두 수행할 수 있다.

## 4. 핵심 기능 요구사항

### 4.1 회원가입 및 로그인
- 이메일, 비밀번호, 닉네임으로 회원가입한다.
- 로그인 및 로그아웃을 지원한다.
- 보호된 기능은 인증된 사용자만 이용할 수 있다.
- 비밀번호는 안전한 해시 방식으로 저장한다.

### 4.2 게시글 관리
사용자는 게시글을 등록·수정·삭제하고 목록과 상세 정보를 조회할 수 있다.

**입력 항목**
- 게시글 유형: 분실물 / 습득물
- 물건명 및 카테고리
- 분실일 또는 습득일
- 장소
- 물건 특징
- 이미지 (선택, 최대 1장)
- 추가 설명 (선택)

작성자는 본인이 등록한 게시글 목록을 확인하고 게시글 상태를 변경할 수 있다. 이미지가 없어도 게시글을 등록할 수 있어야 한다.

### 4.3 게시글 탐색
다음 조건으로 게시글을 검색하고 필터링한다.
- 게시글 유형
- 물건 카테고리
- 물건명 및 키워드
- 장소
- 날짜

검색은 사용자가 지정한 조건으로 게시글을 탐색하는 기능이며, 매칭은 게시글 간 관련성을 계산해 후보를 추천하는 기능이다.

### 4.4 매칭 추천
규칙 기반 점수화로 관련성이 높은 분실물·습득물 게시글을 매칭 후보로 제공한다.

**비교 기준**
- 물건 카테고리
- 장소의 일치 또는 근접성
- 분실일과 습득일의 차이
- 물건 특징의 키워드 유사성

**요구사항**
- 분실물은 습득물과, 습득물은 분실물과 매칭한다.
- 본인이 작성한 게시글은 후보에서 제외한다.
- `찾음` 또는 `반환 완료` 상태의 게시글은 신규 매칭에서 제외한다.
- 후보에 관련성 점수 또는 요약 정보를 제공한다.
- 매칭은 소유자를 확정하는 판정이 아니라 확인이 필요한 후보를 추천하는 기능이다.

점수 배점과 후보 선정 기준은 `MATCHING.md`에서 정의한다.

### 4.5 매칭 결과 확인
- 본인 게시글과 관련된 매칭 후보 목록 및 관련성 정보를 확인한다.
- 매칭 대상 게시글의 상세 정보를 조회한다.
- 매칭 상대와 대화를 시작할 수 있다.
- 반환 완료된 게시글에서는 실제 반환 상대 게시글을 확인할 수 있다.

게시글 상세에는 물건명, 카테고리, 날짜, 장소, 특징, 이미지 및 설명을 표시한다. 소유자 확인에 활용할 비공개 특징은 공개 범위를 제한한다. 매칭 후보와 실제 반환 상대는 구분한다.

### 4.6 1:1 채팅
- 매칭과 연결된 1:1 대화를 제공한다.
- 채팅을 전송하고 대화 내역을 조회할 수 있다.
- 대화 참여자만 해당 대화에 접근할 수 있도록 권한을 확인한다.
- 사용자는 비공개 물건 특징 등을 활용해 소유 여부를 확인하고 반환 방법을 협의한다.
- 게시글 완료 후에도 기존 대화 내역을 조회할 수 있다.

MVP에서는 채팅 저장·전송·조회에 집중하며 대화 상태를 별도로 관리하지 않는다. WebSocket, 읽음 표시, 푸시 알림은 후순위 기능이다.

### 4.7 게시글 상태 및 반환 기록
게시글 상태는 유형에 따라 구분한다.

| 게시글 유형 | 상태 |
|---|---|
| 분실물 | 찾는 중, 찾음 |
| 습득물 | 보관 중, 반환 완료 |

**요구사항**
- 작성자는 본인 게시글의 상태를 변경할 수 있다.
- 반환이 완료되면 실제 반환된 분실물 게시글과 습득물 게시글을 서로 연결하여 기록한다.
- 양쪽 게시글에서 서로를 반환 상대 게시글로 확인할 수 있어야 한다.
- 분실물과 습득물의 상태는 각각 `찾음`, `반환 완료`로 표시한다.
- 실제 반환이 확인된 경우에만 반환 기록을 생성한다.
- 매칭 후보가 발견되었다는 이유만으로 게시글 상태나 반환 기록을 변경하지 않는다.

매칭 후보별 진행 상태와 대화 상태는 MVP에서 별도로 관리하지 않는다.

### 4.8 마이페이지
- 기본 프로필 확인
- 본인이 작성한 게시글 및 상태 확인
- 참여 중인 매칭 후보와 대화 확인
- 반환 완료된 게시글 및 반환 상대 확인

## 5. 화면 구성

**주요 화면**
1. **메인:** 검색, 분실물·습득물 구분, 최근 게시글
2. **게시글 목록:** 게시글 목록 및 검색·필터
3. **게시글 상세:** 물건 정보, 이미지, 작성자 정보, 매칭 및 대화 진입
4. **게시글 등록:** 분실물·습득물 정보 입력 및 이미지 첨부
5. **매칭 결과:** 관련 게시글 및 관련성 확인
6. **채팅:** 대화 목록 및 1:1 대화

**보조 화면**
- 회원가입 및 로그인
- 마이페이지

세부 화면과 이동 흐름은 `SCREEN.md`에서 정의한다. 지도 기반 조회는 초기 필수 범위에서 제외한다.

## 7. 기술 스택 및 시스템 구성

### 7.1 기술 스택

| 영역 | 기술 | 목적 |
|---|---|---|
| 프론트엔드 | Flutter, Dart | 모바일 앱 |
| 백엔드 | Java 21, Spring Boot | REST API 및 서비스 로직 |
| 데이터베이스 | PostgreSQL | 사용자·게시글·반환 기록·채팅 데이터 |
| 이미지 저장소 | Cloudinary | 게시글 이미지 저장 및 조회 |
| CI | GitHub Actions | 변경된 코드의 자동 빌드 및 테스트 |
| 배포 | Render | 백엔드 배포 및 데이터베이스 연동 |
| 형상 관리 | Git, GitHub | 코드 관리 및 협업 |

추가 기술은 필요에 따라 선택한다. Redis, WebSocket, CI/CD는 도입 자체를 목표로 하지 않는다.

### 7.2 시스템 구성
Flutter 앱은 REST API를 호출하고, Spring Boot 서버는 PostgreSQL을 통해 사용자·게시글·반환 기록·채팅 데이터를 관리한다.

게시글 이미지는 Cloudinary에 저장하고, PostgreSQL에는 이미지 식별자와 URL 등 필요한 정보를 저장한다. 이미지 업로드는 사용자 권한을 확인하며, 비밀 API 키를 Flutter 앱에 포함하지 않는다. 구체적인 업로드 방식은 구현 단계에서 결정한다.

배포 환경에서도 API 연동과 이미지 업로드·조회가 정상적으로 동작하도록 검증한다. 프로젝트 실행 방법과 구조는 `README.md`에서 관리한다.

## 8. 비기능 요구사항

### 8.1 보안 및 개인정보 보호
- 비밀번호는 평문으로 저장하지 않는다.
- 인증 및 게시글 수정·삭제 권한을 확인한다.
- 채팅 접근 시 대화 참여자 여부를 확인한다.
- 소유자 확인에 필요한 민감한 정보는 불필요하게 공개하지 않는다.
- 데이터베이스 접속 정보와 인증 비밀값은 환경 변수 등으로 관리한다.
- 이미지의 허용 파일 형식과 크기를 제한한다.

### 8.2 데이터 및 오류 처리
- 잘못된 요청과 존재하지 않는 리소스에 적절한 오류를 반환한다.
- 게시글 상태와 반환 기록의 일관성을 유지한다.
- 완료된 게시글의 신규 매칭을 방지한다.
- 반환 상대는 유효한 반대 유형 게시글인지 확인한다.
- 이미지 업로드 실패 및 이미지 조회 오류를 처리한다.

### 8.3 배포 및 실행
- 개발 환경과 배포 환경의 설정을 분리한다.
- 배포 환경에서 백엔드·데이터베이스·모바일 앱 간 연동을 검증한다.
- 핵심 사용자 시나리오를 배포 환경에서 테스트한다.

## 12. 프로젝트 최종 목표

분실물과 습득물 사이의 관련성을 계산하고 사용자 간 소통을 통해 반환 과정을 지원하는 모바일 서비스를 구현한다.

핵심 기능의 완성, 적절한 데이터 설계, 사용자 권한 보호 및 실제 배포 환경에서의 동작 검증을 우선한다.
