# 잇다 — 화면 설계

## 1. 설계 원칙

- 모바일 애플리케이션을 기준으로 설계한다.
- 카카오 로그인을 통해 인증하며, 최초 로그인 성공 시 서비스 계정을 생성한다.
- 로그인 사용자만 게시글 탐색·등록, 채팅 및 마이페이지 기능을 이용할 수 있다.
- 하단 네비게이션 바는 `홈`, `등록`, `채팅`, `마이페이지`로 구성한다.
- 게시글 등록과 수정은 동일한 화면을 사용한다.
- 매칭은 관련 게시글을 추천하는 기능이며, 실제 소유자 확인이나 반환 완료를 의미하지 않는다.
- 매칭 후보는 작성자의 게시글 상세 화면에서 제공하며 별도 매칭 결과 화면은 두지 않는다.
- 반환 완료 처리와 반환 기록 취소는 채팅방에서 진행한다.
- 게시글 이미지는 선택 사항이며 게시글당 최대 5장까지 첨부할 수 있다.
- 채팅은 텍스트·이미지 메시지와 메시지 푸시 알림을 지원한다. WebSocket 기반 실시간 채팅과 읽음 표시는 후순위 기능이다.
- 알림 목록 조회, 게시글 신고 및 사용자 차단은 후순위 기능이다.
- API 명세는 [API](api.yaml), 데이터 구조는 [ERD](ERD.md), 매칭 기준은 [MATCHING](MATCHING.md)을 참고한다.

## 3. 화면 간 이동 흐름

### 3.1 로그인 및 서비스 진입

1. 앱 실행 시 로그인 상태를 확인한다.
2. 비로그인 상태라면 카카오 로그인 화면으로 이동한다.
3. 카카오 인증에 성공하면 서버에서 인증 결과를 검증한다.
4. 최초 로그인이라면 서비스 계정을 생성하고, 기존 사용자라면 기존 계정으로 로그인한다.
5. 로그인이 완료되면 홈 화면으로 이동한다.

### 3.2 게시글 탐색 및 등록

1. 홈 화면에서 `주웠어요` 또는 `잃어버렸어요` 탭으로 게시글을 탐색한다.
2. 검색바를 선택하면 게시글 검색·필터 화면으로 이동한다.
3. 검색어를 실행하면 최근 검색어에 저장하고 검색 결과를 표시한다.
4. 최근 검색어를 선택하면 해당 검색어로 검색을 다시 실행한다.
5. 게시글을 선택하면 상세 화면으로 이동한다.
6. 본인 게시글 상세 화면에서 매칭 후보를 확인한다.
7. 등록 탭에서 게시글 유형을 선택한 뒤 등록 화면으로 이동한다.
8. 등록이 완료되면 해당 게시글의 상세 화면으로 이동한다.
9. 본인 게시글의 수정·삭제는 상세 화면에서 진행한다.

### 3.3 매칭 및 채팅

1. 본인 게시글 상세 화면에서 매칭 후보와 관련성 점수를 확인한다.
2. 후보를 선택하면 해당 게시글의 상세 정보를 확인한다.
3. 다른 사용자의 게시글 상세 화면에서 대화를 시작할 수 있다. 대화를 시작하는 사용자에게 대응하는 반대 유형 게시글이 없어도 된다.
4. 첫 메시지 전송 시 기존 채팅방이 있는지 확인하고, 있으면 재사용하고 없으면 생성한다.
5. 채팅에서 물건의 비공개 특징 등을 확인하고 반환 방법을 협의한다.

### 3.4 반환 처리

반환 완료 및 반환 기록 취소는 채팅방에서 진행한다. 처리 권한, 기한, 게시글 상태 변경 및 취소 후 동작은 7장을 따른다.

## 4. 화면별 설계

### 4.1 SCR-01. 홈

**목적**

주요 기능으로 진입하고 분실물·습득물 게시글을 탐색한다.

**주요 UI 요소**

- 검색바
- 게시글 유형 탭: `주웠어요`, `잃어버렸어요`
- 게시글 목록

**표시 규칙**

- 최초 진입 시 `주웠어요` 탭을 선택한다.
- `주웠어요`는 습득물 게시글, `잃어버렸어요`는 분실물 게시글을 의미한다.
- 탭을 변경하면 해당 유형의 게시글을 표시한다.
- 게시글 목록은 무한 스크롤로 탐색한다.

**사용자 액션**

| 액션 | 처리 결과 |
|---|---|
| 검색바 선택 | 게시글 검색·필터 화면으로 이동 |
| 게시글 유형 탭 선택 | 해당 유형의 게시글 표시 |
| 게시글 선택 | 게시글 상세 화면으로 이동 |

빈 목록 및 공통 오류 처리는 6장을 따른다.

### 4.2 SCR-02. 게시글 검색·필터

**목적**

분실물·습득물 게시글을 검색하고 조건에 따라 결과를 좁히며, 최근 검색어를 다시 사용한다.

**주요 UI 요소**

- 키워드 입력창 및 검색 실행 버튼
- 게시글 상태 필터
- 카테고리 필터
- 날짜 및 장소 필터
- 최근 검색어 목록
- 최근 검색어 전체 삭제 버튼
- 검색 결과 목록
- 필터 초기화 버튼

**검색 및 필터 규칙**

- 게시글 상태, 카테고리, 키워드, 날짜, 장소를 검색 조건으로 활용한다.
- 키워드 검색을 실행하면 검색어를 최근 검색어로 저장한다.
- 최근 검색어는 검색 화면에서 다시 선택해 사용할 수 있다.
- 사용자는 최근 검색어를 개별 삭제하거나 전체 삭제할 수 있다.
- 최근 검색어 저장 방식과 보관 범위는 세부 설계에서 정의한다.
- 반환 완료 상태의 게시글도 일반 목록에서 조회할 수 있다. 단, 신규 매칭 후보에서는 제외한다.

**사용자 액션**

| 액션 | 처리 결과 |
|---|---|
| 검색 실행 | 검색어를 최근 검색어에 저장하고 조건에 맞는 게시글 표시 |
| 최근 검색어 선택 | 선택한 검색어로 검색 실행 |
| 최근 검색어 개별 삭제 | 선택한 검색어 삭제 |
| 최근 검색어 전체 삭제 | 저장된 최근 검색어 모두 삭제 |
| 필터 선택 | 선택한 조건에 맞게 결과 갱신 |
| 필터 초기화 | 검색 필터를 기본 조건으로 복구 |
| 게시글 선택 | 게시글 상세 화면으로 이동 |
| 뒤로 가기 | 이전 화면으로 복귀 |

검색 결과가 없으면 조건에 맞는 게시글이 없다는 안내를 표시한다. 최근 검색어가 없으면 해당 영역에 검색어가 없다는 안내를 표시한다.

### 4.3 SCR-03. 게시글 상세

**목적**

게시글의 상세 정보를 확인하고, 본인 게시글의 매칭 후보를 확인하거나 다른 사용자와 대화를 시작한다.

**주요 UI 요소**

- 게시글 이미지
- 게시글 유형 및 상태
- 카테고리
- 물건명
- 작성자 닉네임
- 날짜 및 장소
- 특징
- `작성자 전용` 매칭 후보 목록 및 관련성 점수
- `비작성자 전용` 채팅 시작 버튼
- `작성자 전용` 수정·삭제 버튼
- 반환 완료 상태에서 확인 가능한 실제 반환 상대 게시글 정보

**매칭 후보 표시 규칙**

- 후보 목록은 해당 게시글의 작성자에게만 표시한다.
- 분실물에는 습득물, 습득물에는 분실물을 후보로 제공한다.
- 본인 게시글과 반환 완료 상태의 게시글은 신규 후보에서 제외한다.
- 분실물은 `찾는 중`, 습득물은 `보관 중` 상태인 게시글만 후보로 제공한다.
- 후보별 관련성 점수를 표시한다.
- 매칭 후보는 소유자 확정이 아니며, 사용자가 실제 소유 여부를 확인해야 한다.
- 후보 선정 기준과 점수 계산 방식은 [MATCHING](MATCHING.md)을 따른다.

**사용자 액션**

| 액션 | 처리 결과 |
|---|---|
| 매칭 후보 선택 | 해당 게시글 상세 화면으로 이동 |
| 채팅 시작 선택 | 첫 메시지 전송 시 기존 채팅방을 재사용하거나 새로 생성한 뒤 채팅방으로 이동 |
| 수정 선택 | 수정 가능한 게시글인지 확인한 뒤 등록·수정 화면을 수정 모드로 열기 |
| 삭제 선택 | 삭제 가능한 게시글인지 확인한 뒤 삭제 처리 |
| 반환 상대 게시글 선택 | 연결된 게시글 상세 화면으로 이동 |
| 뒤로 가기 | 이전 화면으로 복귀 |

**상태별 표시**

- 매칭 후보가 없으면 후보 목록 영역에 결과가 없다는 안내를 표시한다.
- 반환 기록이 취소된 경우 현재 게시글 상태를 표시한다.
- 반환 완료 상태의 게시글에는 수정·삭제 기능을 제공하지 않는다.
- 삭제되었거나 조회할 수 없는 게시글은 상세 정보를 제공하지 않고 안내한다.

권한 검증 및 게시글 상태에 따른 처리 가능 여부는 5장과 7장을 따른다.

### 4.4 SCR-04. 게시글 등록·수정

**목적**

분실물 또는 습득물 게시글을 등록하거나 기존 게시글을 수정한다.

**화면 구성**

등록과 수정은 동일한 폼을 사용한다. 수정 모드에서는 기존 게시글 정보를 입력 필드에 표시한다.

**주요 UI 요소**

- 게시글 유형 선택: `주웠어요`, `잃어버렸어요`
- 카테고리 선택
- 물건명 입력
- 날짜 입력
- 장소 입력
- 특징 입력
- 이미지 첨부 및 미리보기
- 등록 또는 수정 완료 버튼
- 취소 버튼

**입력 규칙**

- 게시글 유형, 카테고리, 물건명, 날짜 및 장소는 필수 항목으로 입력한다. 특징과 이미지는 선택 항목이다.
- 이미지는 게시글당 최대 5장까지 첨부할 수 있다.
- 이미지의 허용 파일 형식과 최대 크기는 미결정 사항으로 관리한다.
- 필수 입력 항목과 입력 형식은 [API](api.yaml)를 따른다.

**사용자 액션**

| 액션 | 처리 결과 |
|---|---|
| 게시글 유형 선택 | 해당 유형에 맞는 입력 폼 표시 |
| 이미지 첨부 | 이미지 미리보기 표시 |
| 이미지 제거 | 선택한 이미지를 첨부 목록에서 제거 |
| 등록 완료 | 입력값 검증 후 게시글 생성, 상세 화면으로 이동 |
| 수정 완료 | 입력값 검증 후 변경 사항 저장, 상세 화면으로 이동 |
| 취소 | 저장하지 않고 이전 화면으로 복귀 |

필수 입력값이 누락되면 해당 항목에 오류를 표시한다. 이미지 업로드 실패 시 실패 사실을 안내하고 재시도할 수 있도록 한다. 반환 완료 상태의 게시글은 수정·삭제할 수 없다. 권한 및 상태 검증은 서버에서 수행한다.

### 4.5 SCR-05. 채팅 목록

**목적**

사용자가 참여 중인 채팅방을 확인하고 대화를 이어간다.

**주요 UI 요소**

- 상대방 닉네임
- 연결된 게시글 이미지 또는 게시글 유형 아이콘
- 마지막 메시지 내용 일부
- 마지막 메시지 시각

**표시 규칙**

- 마지막 메시지 시각을 기준으로 최신순 정렬한다.
- 연결된 게시글이 삭제되었거나 이미지가 없는 경우 게시글 유형 아이콘을 표시한다.
- 반환 완료 또는 반환 기록 취소 이후에도 기존 채팅 목록을 유지한다.
- 반환 완료 상태의 게시글에 연결된 실제 반환 상대 게시글이 있으면 해당 게시글 정보를 확인할 수 있다.

**사용자 액션**

| 액션 | 처리 결과 |
|---|---|
| 채팅방 선택 | 해당 채팅방으로 이동 |
| 하단 메뉴 선택 | 해당 메뉴 화면으로 이동 |

참여 중인 채팅방이 없으면 빈 목록 안내를 표시한다.

### 4.6 SCR-06. 채팅방

**목적**

두 사용자가 대화하고 실제 반환 여부를 확인하거나 반환 처리를 진행한다.

**주요 UI 요소**

- 연결된 게시글 요약 및 게시글 상세 이동
- 메시지 목록
- 텍스트 입력창 및 전송 버튼
- 이미지 첨부 버튼
- `습득자 전용` 반환 완료 처리 버튼
- `분실자 전용` 반환 기록 취소 버튼

**채팅 기본 동작**

- 채팅방과 메시지는 참여자만 조회하거나 전송할 수 있다.
- 텍스트 및 이미지 메시지를 지원한다.
- 메시지는 저장 후 내역에 표시하며, 기존 메시지를 조회할 수 있다.
- 새 메시지가 도착하면 FCM 푸시 알림을 전송한다. 알림을 선택하면 해당 채팅방으로 이동한다.
- 푸시 알림 전송 실패가 메시지 저장 실패로 이어지지 않도록 한다.
- 반환 완료 및 반환 기록 취소 안내는 채팅 메시지로 전달한다. 별도의 반환 전용 푸시 알림은 제공하지 않는다.
- 반환 완료 또는 반환 기록 취소 이후에도 기존 메시지 내역을 유지한다.
- WebSocket 기반 실시간 송수신과 읽음 표시는 후순위 기능이다.

**게시글 연결 규칙**

- 두 게시글을 연결해 대화를 시작하는 경우, 연결된 분실물은 `찾는 중`, 습득물은 `보관 중` 상태인지 확인한다.
- 다른 사용자의 게시글 상세 화면에서 대화를 시작할 수 있다. 시작하는 사용자에게 대응하는 반대 유형 게시글이 없어도 된다.
- 본인이 작성한 게시글에서는 해당 게시글을 기준으로 대화를 시작할 수 없다.
- 채팅방은 첫 메시지를 전송할 때 생성하며, 메시지가 없는 채팅방은 생성하지 않는다.
- 동일한 참여자와 관련 게시글 조합으로 기존 채팅방이 있으면 재사용한다.
- 연결된 게시글이 삭제된 경우 게시글 요약 영역에 삭제된 게시글로 표시한다.
- 연결된 게시글이 없다면 게시글 요약 및 이동 기능을 제공하지 않는다.

**사용자 액션**

| 액션 | 처리 결과 |
|---|---|
| 텍스트 메시지 전송 | 메시지를 저장하고 내역에 표시 |
| 이미지 첨부 및 전송 | 이미지 메시지를 저장하고 내역에 표시 |
| 연결 게시글 선택 | 연결된 게시글 상세 화면으로 이동 |
| 반환 완료 처리 | 7장에 정의된 절차 수행 |
| 반환 기록 취소 | 7장에 정의된 절차 수행 |
| 뒤로 가기 | 채팅 목록 또는 이전 화면으로 복귀 |

채팅방 접근 권한, 반환 처리 및 공통 메시지 전송 오류 처리는 5~7장을 따른다.

## 5. 공통 동작 및 접근 제어

### 5.1 로그인 및 권한

| 기능 | 접근 규칙 |
|---|---|
| 홈 및 게시글 조회·검색 | 로그인 사용자만 가능 |
| 최근 검색어 관리 | 로그인 사용자만 가능 |
| 게시글 등록·수정·삭제 | 로그인 및 작성자 권한 확인 |
| 매칭 후보 조회 | 로그인 및 해당 게시글 작성자 권한 확인 |
| 채팅 목록 조회 | 로그인 사용자만 가능 |
| 채팅방 접근 및 메시지 송수신 | 로그인 및 참여자 권한 확인 |
| 반환 완료 처리 | 반환 기록에 등록될 습득자 역할 확인 |
| 반환 기록 취소 | 반환 기록에 등록된 분실자 역할 및 7일 이내 여부 확인 |
| 마이페이지 | 로그인 사용자만 가능 |
| 카카오 로그인 | 비로그인 사용자 이용 가능 |

- 비로그인 사용자가 보호된 화면이나 기능에 접근하면 카카오 로그인 화면으로 안내한다.
- 로그인 사용자가 카카오 로그인 화면에 접근하면 홈 화면으로 이동하거나 접근을 제한한다.
- 인증 만료 또는 인증 정보가 유효하지 않으면 인증 정보를 정리하고 로그인 화면으로 이동한다.
- 로그아웃 후 뒤로 가기 등으로 보호된 화면에 다시 접근하지 못하도록 처리한다.
- 실제 인증 및 인가 검증은 서버에서 수행한다. 화면에서 버튼을 숨기는 것만으로 권한을 보장하지 않는다.

### 5.2 게시글 및 채팅 관련 정책

- 게시글의 최신 상태와 처리 권한은 실제 작업을 수행할 때 서버에서 검증한다.
- 반환 완료 상태의 게시글은 수정·삭제할 수 없다. 반환 기록 취소로 상태가 복구되면 일반적인 게시글 수정·삭제 규칙을 적용한다.
- 게시글 상태가 변경되거나 매칭 후보에서 제외되어도 기존 채팅과 반환 기록을 임의로 삭제하지 않는다.
- 반환 기록 취소 후 게시글이 다시 매칭 후보가 되면 기존 채팅방을 재사용한다.
- 채팅방 생성과 첫 메시지 저장은 하나의 처리 단위로 수행하며, 메시지가 없는 채팅방은 생성하지 않는다.

## 6. 공통 예외 처리

모든 화면에 적용되는 로딩, 데이터 없음, 요청 실패 및 권한 오류는 다음 기준을 따른다. 화면별로 별도의 동작이 필요한 경우에만 4장에서 추가로 정의한다.

| 상황 | 화면 동작 |
|---|---|
| 최초 데이터 조회 중 | 로딩 표시 |
| 목록에 데이터가 없음 | 빈 목록 안내 및 가능한 다음 행동 표시 |
| 검색 결과가 없음 | 조건에 맞는 결과가 없다는 안내 |
| 최근 검색어가 없음 | 최근 검색어 영역에 저장된 검색어가 없다는 안내 |
| 서버 요청 실패 | 오류 안내 및 재시도 제공 |
| 필수 입력값 누락 | 해당 입력 항목에 오류 표시 |
| 이미지 업로드 또는 메시지 전송 실패 | 실패 안내 및 재시도 제공 |
| 인증 만료 또는 인증 정보 무효 | 인증 정보를 정리하고 카카오 로그인 화면으로 안내 |
| 권한이 없는 기능에 접근 | 접근을 제한하고 안내 |
| 게시글이 삭제되었거나 조회 불가 | 조회 불가 안내 및 가능한 경우 이전 화면으로 복귀 |
| 매칭 후보의 상태가 변경됨 | 최신 상태 확인 후 진행 제한 안내 |
| 반환 완료 또는 취소 처리 실패 | 최신 상태를 다시 조회하고 결과 안내 |
| 반환 취소 기한 만료 | 취소 불가 안내 |
| 푸시 알림 전송 실패 | 저장된 메시지는 유지하고 알림 전송 실패를 별도로 처리 |

서버 오류 메시지, 인증 정보 및 민감한 시스템 정보를 그대로 노출하지 않는다. 실제 권한과 상태 검증은 서버에서 수행한다.

## 7. 반환 완료 및 반환 기록 취소

### 7.1 게시글 상태 정책

| 게시글 유형 | 반환 전 상태 | 반환 완료 후 상태 |
|---|---|---|
| 분실물 | 찾는 중 | 반환 완료 |
| 습득물 | 보관 중 | 반환 완료 |

- 반환 완료 상태의 게시글은 일반 목록에서 조회할 수 있지만 신규 매칭 후보에서는 제외한다.
- 반환 완료 상태의 게시글은 수정·삭제할 수 없다.
- 반환 기록이 취소되면 연결된 분실물은 `찾는 중`, 습득물은 `보관 중`으로 복구한다.

### 7.2 반환 완료 처리

1. 실제 반환을 진행한 습득자가 반환 여부를 확인한다.
2. 습득자가 채팅방에서 반환 완료 처리를 요청한다.
3. 서버에서 처리 권한, 반환 기록 생성 가능 여부 및 연결된 게시글의 최신 상태를 검증한다.
4. 실제 반환 당사자 정보를 기준으로 반환 기록을 생성한다.
5. 연결된 게시글이 있다면 7.1의 상태 정책에 따라 변경한다.
6. 반환 상대 게시글이 연결되어 있으면 해당 게시글 정보를 확인할 수 있도록 한다.
7. 기존 채팅방과 메시지는 유지한다.

연결된 게시글이 없는 채팅에서도 실제 반환 당사자 정보와 반환 기록을 저장할 수 있다. 이 경우 게시글 상태 변경은 수행하지 않는다. 반환 완료 요청이 중복 처리되지 않도록 한다.

### 7.3 반환 기록 취소

1. 반환 기록에 등록된 분실자 역할 사용자가 기존 채팅방에서 취소 가능 여부를 확인한다.
2. 취소 가능 기간은 반환 완료 처리 시점부터 7일 이내다.
3. 사용자가 취소를 확인하면 서버에서 사용자 권한, 반환 기록 상태 및 기한을 검증한다.
4. 반환 기록을 삭제하지 않고 취소 상태로 변경한다.
5. 연결된 게시글의 상태를 7.1의 정책에 따라 복구한다.
6. 기존 채팅방, 메시지 및 반환 기록 이력을 유지한다.

7일이 지난 경우 일반적인 반환 기록 취소 기능을 제공하지 않는다.

### 7.4 취소 이후 동작

- 취소된 반환 기록은 현재 유효한 반환 완료 기록으로 표시하지 않는다.
- 연결된 게시글은 복구된 상태에 따라 다시 매칭 후보가 될 수 있다.
- 같은 기준 게시글과 참여자 조합으로 대화를 다시 시작하면 기존 채팅방을 재사용한다.
- 같은 당사자가 다시 반환을 진행하면 새로운 반환 기록을 생성한다.
- 취소 가능 여부는 클라이언트 시간이 아닌 서버의 검증 결과를 따른다.
- 기한 만료 또는 처리 실패 시 최신 서버 상태를 기준으로 안내한다.

## 8. 미결정 사항

아래 항목은 아직 구체적인 UI 동작이나 정책이 확정되지 않은 사항이다.

- 서비스 닉네임 설정 화면의 구성
- 빈 목록 및 오류 화면의 구체적인 문구와 시각적 스타일
- 매칭 추천 근거를 표시하는 구체적인 UI 형태
- 회원탈퇴 후 보존되는 데이터의 표시 정보 및 접근 UI
