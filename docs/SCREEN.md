# 잇다 — 화면 설계

## 1. 설계 원칙

- 모바일 애플리케이션을 기준으로 설계한다.
- 하단 네비게이션 바는 `홈`, `등록`, `채팅`, `마이페이지`로 구성한다.
- 게시글 등록과 수정은 동일한 화면을 사용한다.
- 매칭 후보는 작성자의 게시글 상세 화면에서 제공하며 별도 매칭 결과 화면은 두지 않는다.
- 매칭 후보는 실제 소유자를 확정하는 결과가 아니며, 사용자가 실제 소유 여부를 확인해야 한다.
- 반환 완료 처리는 채팅방에서 진행한다.
- 반환 기록 취소는 채팅방과 반환 기록 상세 화면에서 진행할 수 있다.

---

## 2. 공통 컬러 시스템

서비스 전반의 일관된 UI를 위해 다음 컬러 시스템을 적용한다.

| 컬러 이름 | HEX | 용도 |
|---|---|---|
| `yellow` | `#FFD95A` | 주요 버튼, 게시글 등록, 반환 완료 등 핵심 행동 강조 |
| `blue` | `#70C1E8` | 링크, 매칭 정보, 선택된 탭 등 보조 강조 |
| `coral-red` | `#FF8E7B` | 오류 메시지, 삭제 확인, 실패 상태, 위험한 작업에 대한 경고 |
| `black` | `#1A1A1A` | 화면 제목, 본문 텍스트, 게시글 제목 및 주요 정보 |
| `light-yellow` | `#FFF8E7` | 반환 완료 등 특정 상태의 배경 및 부드러운 강조 |
| `gray1` | `#8E8E93` | 보조 설명, 날짜, 장소 등 부가 텍스트 |
| `gray2` | `#AEAEB2` | 플레이스홀더, 비활성 아이콘, 보조 안내 텍스트 |
| `gray3` | `#C7C7CC` | 비활성 컨트롤의 테두리 및 약한 경계선 |
| `gray4` | `#D1D1D6` | 입력창 및 카드의 기본 테두리, 구분선 |
| `gray5` | `#E5E5EA` | 비활성 버튼, 칩 및 필터 영역의 경계 |
| `gray6` | `#F2F2F7` | 보조 배경, 비활성 필터 영역, 카드 내부 배경 |

### 적용 원칙

- 주요 행동에는 `yellow`를, 링크 및 보조 강조에는 `blue`를 사용한다.
- 오류, 삭제 및 위험한 작업에 대한 경고에는 `coral-red`를 사용한다.
- 주요 텍스트에는 `black`을, 부가 정보에는 `gray1`을 사용한다.
- 회색 계열은 텍스트의 중요도, UI 요소의 경계 및 배경의 위계에 따라 구분하여 사용한다.
- 상태는 색상만으로 전달하지 않으며, 텍스트나 아이콘을 함께 사용한다.
- 노란색 배경의 버튼에는 가독성을 고려하여 `black` 텍스트를 사용한다.

## 4. 화면 간 이동 흐름

### 4.1 로그인 및 서비스 진입

1. 앱 실행 시 로그인 상태를 확인한다.
2. 비로그인 상태라면 카카오 로그인 화면으로 이동한다.
3. 카카오 로그인에 성공하면 홈 화면으로 이동한다.
4. 로그인 사용자가 카카오 로그인 화면에 접근하면 홈 화면으로 이동하거나 접근을 제한한다.

인증 및 계정 생성에 관한 상세 정책은 [PRD](PRD.md)와 [API](https://3uznoxlhxz.apidog.io)를 따른다.

### 4.2 게시글 탐색 및 등록

1. 홈 화면에서 `주웠어요` 또는 `잃어버렸어요` 탭으로 게시글을 탐색한다.
2. 검색바를 선택하면 게시글 검색·필터 화면으로 이동한다.
3. 검색어를 입력하고 검색을 실행하면 조건에 맞는 결과를 표시한다.
4. 최근 검색어를 선택하면 해당 검색어로 검색을 다시 실행한다.
5. 게시글을 선택하면 게시글 상세 화면으로 이동한다.
6. 본인 게시글 상세 화면에서 매칭 후보를 확인한다.
7. 등록 탭에서 게시글 유형을 선택한 뒤 등록 화면으로 이동한다.
8. 게시글 등록이 완료되면 해당 게시글의 상세 화면으로 이동한다.
9. 본인 게시글의 수정·삭제는 상세 화면에서 진행한다.

### 4.3 매칭 및 채팅

1. 본인 게시글 상세 화면에서 매칭 후보와 관련성 점수를 확인한다.
2. 매칭 후보를 선택하면 해당 게시글의 상세 정보를 확인한다.
3. 다른 사용자의 게시글 상세 화면에서 채팅을 시작할 수 있다.
4. 채팅 시작 시 기존 채팅방이 있으면 재사용하고, 없으면 첫 메시지 전송 과정에서 새 채팅방을 생성한다.
5. 채팅방에서 물건의 비공개 특징 등을 확인하고 반환 방법을 협의한다.

채팅방 생성 및 재사용의 상세 조건은 [PRD](PRD.md)를 따른다.

### 4.4 반환 처리

1. 채팅방에서 반환 완료 및 취소 기능을 선택한다.
2. 처리 가능 여부를 확인하고 필요한 확인 절차를 진행한다.
3. 처리 결과를 채팅방에서 확인한다.
4. 처리에 실패하면 안내를 표시하고 최신 상태를 반영한다.

반환 처리의 권한, 취소 가능 기간, 게시글 상태 변경 및 데이터 처리 정책은 [PRD](PRD.md)를 따른다.

### 4.5 반환 기록 조회 및 취소

1. 마이페이지에서 반환 기록 목록으로 이동한다.
2. 반환 기록 목록에서 반환 기록을 선택하면 반환 기록 상세 화면으로 이동한다.
3. 반환 기록 상세 화면에서 연결된 습득물·분실물 게시글 정보를 확인한다.
4. 게시글 제목을 선택하면 해당 게시글 상세 화면으로 이동한다.
5. 채팅방으로 이동 버튼을 선택하면 해당 반환 기록과 연결된 채팅방으로 이동한다.
6. 분실자는 반환 기록 상세 화면에서 취소 기능을 이용할 수 있다.
7. 반환 기록 취소에 성공하면 반환 기록과 관련 게시글의 최신 상태를 반영한다.

반환 기록 조회 및 취소의 권한, 반환 기록 상태 및 취소 가능 기간은 [PRD](PRD.md)를 따른다.

## 5. 화면별 설계

### 5.1 SCR-01. 홈

**목적**

주요 기능으로 진입하고 분실물·습득물 게시글을 탐색한다.

**주요 UI 요소**

- 검색바
- 게시글 유형 탭: `주웠어요`, `잃어버렸어요`
- 게시글 목록

**표시 규칙**

- 최초 진입 시 `주웠어요` 탭을 선택한다.
- `주웠어요`는 습득물 게시글, `잃어버렸어요`는 분실물 게시글을 의미한다.
- 탭을 변경하면 해당 유형의 게시글을 표시한다.
- 게시글 목록은 무한 스크롤로 탐색한다.

**사용자 액션**

| 액션 | 처리 결과 |
|---|---|
| 검색바 선택 | 게시글 검색·필터 화면으로 이동 |
| 게시글 유형 탭 선택 | 해당 유형의 게시글 표시 |
| 게시글 선택 | 게시글 상세 화면으로 이동 |

빈 목록 및 공통 오류 처리는 6장과 7장을 따른다.

### 5.2 SCR-02. 게시글 검색·필터

**목적**

분실물·습득물 게시글을 검색하고 조건에 따라 결과를 좁히며, 최근 검색어를 다시 사용한다.

**주요 UI 요소**

- 키워드 입력창 및 검색 실행 버튼
- 게시글 상태 필터
- 카테고리 필터
- 날짜 및 장소 필터
- 최근 검색어 목록
- 최근 검색어 개별 삭제 버튼
- 최근 검색어 전체 삭제 버튼
- 검색 결과 목록
- 필터 초기화 버튼

**표시 규칙**

- 게시글 상태, 카테고리, 키워드, 날짜, 장소를 검색 조건으로 활용한다.
- 검색 실행 후 조건에 맞는 게시글 목록을 표시한다.
- 최근 검색어는 검색 화면에서 다시 선택해 사용할 수 있다.
- 최근 검색어는 개별 삭제하거나 전체 삭제할 수 있다.
- 반환 완료 상태의 게시글도 일반 검색 결과에 표시할 수 있다.
- 최근 검색어의 저장 방식과 보관 정책은 [PRD](PRD.md)를 따른다.

**사용자 액션**

| 액션 | 처리 결과 |
|---|---|
| 검색 실행 | 최근 검색어를 저장하고 조건에 맞는 게시글 표시 |
| 최근 검색어 선택 | 선택한 검색어로 검색 실행 |
| 최근 검색어 개별 삭제 | 선택한 검색어 삭제 |
| 최근 검색어 전체 삭제 | 저장된 최근 검색어 모두 삭제 |
| 필터 선택 | 선택한 조건에 맞게 결과 갱신 |
| 필터 초기화 | 검색 필터를 기본 조건으로 복구 |
| 게시글 선택 | 게시글 상세 화면으로 이동 |
| 뒤로 가기 | 이전 화면으로 복귀 |

검색 결과가 없으면 조건에 맞는 게시글이 없다는 안내를 표시한다. 최근 검색어가 없으면 해당 영역에 검색어가 없다는 안내를 표시한다.

### 5.3 SCR-03. 게시글 상세

**목적**

게시글의 상세 정보를 확인하고, 본인 게시글의 매칭 후보를 확인하거나 다른 사용자와 대화를 시작한다.

**주요 UI 요소**

- 게시글 이미지
- 게시글 유형 및 상태
- 카테고리
- 제목
- 작성자 닉네임
- 날짜 및 장소
- 설명
- `작성자 전용` 매칭 후보 목록 및 관련성 점수
- `비작성자 전용` 채팅 시작 버튼
- `작성자 전용` 수정·삭제 버튼
- `반환 완료 상태` 실제 반환 상대 게시글 정보

**표시 규칙**

- 매칭 후보 목록은 해당 게시글의 작성자에게 표시한다.
- 분실물 게시글에는 습득물 게시글, 습득물 게시글에는 분실물 게시글을 후보로 표시한다.
- 매칭 후보별 관련성 점수를 표시한다.
- 매칭 후보가 없으면 후보 목록 영역에 결과가 없다는 안내를 표시한다.
- 매칭 후보는 실제 소유자를 확정하는 결과가 아님을 명확히 한다.
- 반환 완료 상태의 게시글에는 수정·삭제 기능을 제공하지 않는다.
- 반환 기록 취소로 게시글 상태가 복구된 경우 현재 상태를 반영한다.
- 삭제되었거나 조회할 수 없는 게시글은 상세 정보를 제공하지 않고 안내한다.

매칭 후보의 선정 기준과 점수 계산 방식은 [MATCHING](MATCHING.md), 게시글 상태와 수정·삭제 가능 여부에 관한 상세 정책은 [PRD](PRD.md)를 따른다.

**사용자 액션**

| 액션 | 처리 결과 |
|---|---|
| 매칭 후보 선택 | 해당 게시글 상세 화면으로 이동 |
| 채팅 시작 선택 | 채팅방으로 이동 |
| 수정 선택 | 등록·수정 화면을 수정 모드로 열기 |
| 삭제 선택 | 삭제 확인 절차 진행 후 결과 안내 |
| 반환 상대 게시글 선택 | 연결된 게시글 상세 화면으로 이동 |
| 뒤로 가기 | 이전 화면으로 복귀 |

수정·삭제할 수 없는 게시글이거나 매칭 후보의 상태가 변경된 경우, 사용자에게 처리할 수 없다는 안내를 표시하고 최신 상태를 반영한다.

### 5.4 SCR-04. 게시글 등록·수정

**목적**

분실물 또는 습득물 게시글을 등록하거나 기존 게시글을 수정한다.

**화면 구성**

등록과 수정은 동일한 폼을 사용한다. 수정 모드에서는 기존 게시글 정보를 입력 필드에 표시한다.

**주요 UI 요소**

- 게시글 유형 선택: `주웠어요`, `잃어버렸어요`
- 카테고리 선택
- 제목 입력
- 날짜 입력
- 장소 입력
- 설명 입력
- 이미지 첨부 및 미리보기
- 등록 또는 수정 완료 버튼
- 취소 버튼

**입력 규칙**

- 게시글 유형, 카테고리, 제목, 날짜 및 장소는 필수 항목이다.
- 설명과 이미지는 선택 항목이다.
- 이미지는 게시글당 최대 5장까지 첨부할 수 있다.
- 이미지 첨부 시 미리보기를 표시한다.
- 첨부된 이미지는 개별적으로 제거할 수 있다.

**사용자 액션**

| 액션 | 처리 결과 |
|---|---|
| 게시글 유형 선택 | 해당 유형에 맞는 입력 폼 표시 |
| 이미지 첨부 | 이미지 미리보기 표시 |
| 이미지 제거 | 선택한 이미지를 첨부 목록에서 제거 |
| 등록 완료 | 입력값 검증 후 게시글 생성, 상세 화면으로 이동 |
| 수정 완료 | 입력값 검증 후 변경 사항 저장, 상세 화면으로 이동 |
| 취소 | 저장하지 않고 이전 화면으로 복귀 |

필수 입력값이 누락되면 해당 항목에 오류를 표시한다. 이미지 업로드에 실패하면 실패 사실을 안내하고 재시도할 수 있도록 한다. 수정·삭제가 불가능한 게시글은 최신 상태를 반영하고 안내한다.

이미지 파일 형식 및 크기 제한은 [PRD](PRD.md)의 미결정 사항을 따른다.

### 5.5 SCR-05. 채팅 목록

**목적**

사용자가 참여 중인 채팅방을 확인하고 대화를 이어간다.

**주요 UI 요소**

- 상대방 닉네임
- 연결된 게시글 이미지 또는 게시글 유형 아이콘
- 마지막 메시지 내용 일부
- 마지막 메시지 시각

**표시 규칙**

- 마지막 메시지 시각을 기준으로 최신순 정렬한다.
- 연결된 게시글이 삭제되었거나 이미지가 없는 경우 게시글 유형 아이콘을 표시한다.
- 반환 완료 또는 반환 기록 취소 이후에도 기존 채팅 목록을 유지한다.
- 반환 기록과 연결된 게시글 정보는 채팅방에서 확인할 수 있다.

**사용자 액션**

| 액션 | 처리 결과 |
|---|---|
| 채팅방 선택 | 해당 채팅방으로 이동 |
| 하단 메뉴 선택 | 해당 메뉴 화면으로 이동 |

참여 중인 채팅방이 없으면 빈 목록 안내를 표시한다.

### 5.6 SCR-06. 채팅방

**목적**

두 사용자가 대화하고 실제 반환 여부를 확인하거나 반환 처리를 진행한다.

**주요 UI 요소**

- 연결된 게시글 요약 및 게시글 상세 이동
- 메시지 목록
- 텍스트 입력창 및 전송 버튼
- 이미지 첨부 버튼
- `습득자 전용` 반환 완료 처리 버튼
- `분실자 전용` 반환 기록 취소 버튼
- `반환 처리 메시지` 반환 기록 상세 화면 이동 버튼

**채팅 표시 및 동작**

- 텍스트 및 이미지 메시지를 지원한다.
- 기존 메시지 내역을 조회할 수 있다.
- 전송한 메시지는 저장 결과를 반영해 메시지 목록에 표시한다.
- 새 메시지가 도착하면 푸시 알림을 전송하며, 알림을 선택하면 해당 채팅방으로 이동한다.
- 반환 완료 및 취소 안내는 채팅 메시지로 전달한다.
- 별도의 반환 전용 푸시 알림은 제공하지 않는다.
- 반환 완료 또는 반환 기록 취소 이후에도 기존 메시지 내역을 유지한다.
- WebSocket 기반 실시간 송수신과 읽음 표시는 후순위 기능이다.

**게시글 표시**

- 연결된 게시글이 삭제된 경우 게시글 요약 영역에 삭제된 게시글임을 표시한다.
- 연결된 게시글이 없으면 게시글 요약 및 이동 기능을 제공하지 않는다.
- 연결된 게시글을 선택하면 해당 게시글의 상세 화면으로 이동한다.

**사용자 액션**

| 액션 | 처리 결과 |
|---|---|
| 텍스트 메시지 전송 | 메시지 전송 결과를 반영하고 내역에 표시 |
| 이미지 첨부 및 전송 | 이미지 메시지 전송 결과를 반영하고 내역에 표시 |
| 연결 게시글 선택 | 연결된 게시글 상세 화면으로 이동 |
| 반환 완료 처리 선택 | 반환 완료 처리 절차 진행 |
| 반환 기록 취소 선택 | 반환 기록 취소 절차 진행 |
| 반환 기록 보기 선택 | 해당 반환 기록 상세 화면으로 이동 |
| 뒤로 가기 | 채팅 목록 또는 이전 화면으로 복귀 |

**반환 처리 결과**

- 반환 완료 처리가 성공하면 결과를 안내하고 관련 화면 정보를 갱신한다.
- 반환 처리 메시지에 반환 기록 상세 화면으로 이동할 수 있는 기능을 제공한다.
- 반환 기록 취소가 성공하면 결과를 안내하고 관련 화면 정보를 갱신한다.
- 취소할 수 없는 기록이면 취소 불가 사유를 안내한다.
- 처리에 실패하면 오류를 안내하고 최신 상태를 반영한다.
- 반환 처리 이후에도 기존 채팅방과 메시지 내역을 유지한다.

반환 처리 및 채팅방 생성·재사용, 메시지 전송에 관한 상세 정책은 [PRD](PRD.md)를 따른다.

### 5.7 SCR-07. 카카오 로그인

**목적**

카카오 계정으로 사용자를 인증하고 서비스에 진입한다.

**주요 UI 요소**

- 카카오 로그인 버튼
- 로그인 처리 중 표시
- 인증 실패 안내

**사용자 액션**

| 액션 | 처리 결과 |
|---|---|
| 카카오 로그인 선택 | 카카오 인증 절차 시작 |
| 인증 성공 | 홈 화면으로 이동 |
| 인증 취소 | 로그인 화면에 머물며 취소 안내 표시 |
| 인증 실패 | 오류 안내 및 재시도 제공 |

최초 로그인 시 계정 생성과 인증 결과 검증은 [PRD](PRD.md) 및 [API](https://3uznoxlhxz.apidog.io)를 따른다. 서비스 닉네임 최초 설정 방식은 미결정 사항으로 관리한다.

### 5.8 SCR-08. 반환 기록 목록

**목적**

본인이 참여한 반환 기록을 확인하고 상세 정보를 조회한다.

**주요 UI 요소**

- 반환 상태
- 반환 시각
- 연결된 습득물 게시글 제목
- 연결된 분실물 게시글 제목

**표시 규칙**

- 반환 기록은 `반환 완료` 및 `반환 취소` 상태를 구분하여 표시한다.
- 반환 기록은 생성 시각을 기준으로 최신순 정렬한다.
- 습득물 게시글과 분실물 게시글 제목을 각각 구분하여 표시한다.
- 한쪽 게시글만 연결되어 있으면 해당 게시글 제목을 표시하고, 다른 쪽은 연결된 게시글 없음을 표시한다.
- 연결된 게시글이 삭제된 경우 해당 게시글 제목 대신 삭제된 게시글임을 표시한다.
- 반환 기록이 취소된 경우 취소 시각을 확인할 수 있도록 한다.
- 반환 기록이 없으면 반환 기록이 없다는 안내를 표시한다.

**사용자 액션**

| 액션 | 처리 결과 |
|---|---|
| 반환 기록 선택 | 해당 반환 기록 상세 화면으로 이동 |
| 뒤로 가기 | 마이페이지로 복귀 |

### 5.9 SCR-09. 반환 기록 상세

**목적**

반환 기록의 상세 정보와 실제 반환 상대, 관련 게시글을 확인하고 채팅방으로 이동하거나 반환 기록을 취소한다.

**주요 UI 요소**

- 반환 기록 상태
- 반환 완료 시각
- `반환 취소 상태` 반환 취소 시각
- 습득물 게시글 정보 영역
- 분실물 게시글 정보 영역
- 채팅방 이동 버튼
- `분실자 전용` 반환 기록 취소 버튼

**게시글 정보 영역**

습득물 게시글과 분실물 게시글을 각각 독립된 영역으로 표시한다.

```text
습득물 게시글 제목 >
작성자 닉네임

분실물 게시글 제목 >
작성자 닉네임
```

한쪽 게시글만 연결된 경우:

```text
습득물 게시글 제목 >
작성자 닉네임

연결된 게시글 없음
작성자 닉네임
```

**표시 규칙**

- 습득물 게시글 정보와 분실물 게시글 정보를 각각 별도의 영역으로 표시한다.
- 각 영역에는 게시글 제목과 작성자 닉네임을 표시한다.
- 게시글 제목이 있는 경우 클릭 가능한 행으로 표시하고, 행 끝에 이동 표시를 제공한다.
- 게시글 제목을 선택하면 해당 게시글 상세 화면으로 이동한다.
- 한쪽 게시글이 연결되어 있지 않아도 해당 게시글 유형의 영역을 유지한다.
- 연결된 게시글이 없는 영역에는 연결된 게시글 없음을 표시한다.
- 게시글이 삭제된 경우 해당 게시글 영역에 삭제된 게시글임을 표시한다.
- 채팅방 이동 버튼을 선택하면 해당 반환 기록과 연결된 채팅방으로 이동한다.
- 반환 기록이 취소된 경우 취소 시각을 표시한다.
- 반환 기록 취소 기능은 분실자 역할의 사용자에게만 표시한다.

**사용자 액션**

| 액션 | 처리 결과 |
|---|---|
| 습득물 게시글 제목 선택 | 해당 반환 기록 상세 화면으로 이동 |
| 분실물 게시글 제목 선택 | 해당 분실물 게시글 상세 화면으로 이동 |
| 채팅방 이동 선택 | 연결된 채팅방으로 이동 |
| 반환 기록 취소 선택 | 반환 기록 취소 절차 진행 |
| 뒤로 가기 | 반환 기록 목록 화면으로 복귀 |

**반환 기록 취소**

- 반환 기록 취소 버튼을 선택하면 취소 확인 절차를 진행한다.
- 취소 확인 후 서버에 반환 기록 취소를 요청한다.
- 취소에 성공하면 반환 기록 상태와 관련 게시글의 최신 상태를 반영한다.
- 취소에 실패하면 오류를 안내하고 최신 상태를 반영한다.
- 취소할 수 없는 기록이면 취소 불가 사유를 안내한다.
- 반환 기록 취소 후에도 기존 채팅방, 메시지 및 반환 기록 이력을 유지한다.

반환 기록 조회, 채팅방 이동, 반환 기록 취소의 권한 및 처리 규칙은 [PRD](PRD.md)를 따른다.

### 5.10 SCR-10. 마이페이지

**목적**

프로필, 본인 게시글, 반환 기록을 확인하고 계정 기능을 이용한다.

**주요 UI 요소**

- 프로필 영역: 닉네임
- 내 습득물 게시글 목록
- 내 분실물 게시글 목록
- 반환 기록 목록
- 로그아웃 버튼
- 회원탈퇴 버튼

**사용자 액션**

| 액션 | 처리 결과 |
|---|---|
| 프로필 영역 선택 | 프로필 수정 화면으로 이동 |
| 내 습득물 게시글 선택 | 해당 게시글 상세 화면으로 이동 |
| 내 분실물 게시글 선택 | 해당 게시글 상세 화면으로 이동 |
| 반환 기록 선택 | 반환 기록 목록 화면으로 이동 |
| 로그아웃 선택 | 로그아웃 처리 후 카카오 로그인 화면으로 이동 |
| 회원탈퇴 선택 | 탈퇴 안내 및 확인 절차 진행 |

- 본인 게시글과 반환 기록이 없으면 해당 안내를 표시한다.
- 반환 완료 기록은 현재 유효한 기록과 취소된 이력을 구분해 표시한다.
- 로그아웃 처리 결과에 따라 로그인 화면으로 이동한다.

로그아웃 시 기기 토큰 처리와 회원탈퇴 후 데이터 보존 정책은 [PRD](PRD.md)를 따른다.

### 5.11 SCR-11. 프로필 수정

**목적**

사용자가 서비스에서 사용할 닉네임을 설정하거나 수정한다.

**주요 UI 요소**

- 현재 닉네임
- 닉네임 입력 필드
- 저장 버튼
- 취소 버튼

**사용자 액션**

| 액션 | 처리 결과 |
|---|---|
| 닉네임 저장 | 입력값 검증 후 변경 사항 저장 |
| 취소 | 변경 사항을 저장하지 않고 마이페이지로 복귀 |

입력값이 유효하지 않거나 저장에 실패하면 해당 내용을 안내하고 수정할 수 있도록 한다.

### 5.12 SCR-12. 회원탈퇴

**목적**

사용자가 탈퇴 안내와 유의사항을 확인하고 회원탈퇴를 요청한다.

**주요 UI 요소**

- 회원탈퇴 안내 및 유의사항
- 탈퇴 확인 영역
- 탈퇴 버튼
- 취소 버튼

**사용자 액션**

| 액션 | 처리 결과 |
|---|---|
| 탈퇴 요청 | 확인 절차 후 탈퇴 요청 |
| 탈퇴 성공 | 로그인 화면으로 이동 |
| 탈퇴 실패 | 오류 안내 및 가능한 경우 재시도 제공 |
| 취소 | 탈퇴하지 않고 마이페이지로 복귀 |

탈퇴 후 계정, 게시글, 채팅방, 메시지 및 반환 기록의 삭제·보존 정책은 [PRD](PRD.md)를 따른다.

## 6. 공통 화면 동작

### 6.1 로그인 상태에 따른 화면 이동

- 비로그인 사용자가 로그인이 필요한 화면이나 기능에 접근하면 카카오 로그인 화면으로 안내한다.
- 로그인 사용자가 카카오 로그인 화면에 접근하면 홈 화면으로 이동하거나 접근을 제한한다.
- 인증이 만료되거나 유효하지 않으면 인증 정보를 정리하고 카카오 로그인 화면으로 안내한다.
- 로그아웃 후 뒤로 가기 등으로 보호된 화면에 다시 접근하지 못하도록 처리한다.

### 6.2 게시글 및 채팅 화면 갱신

- 게시글 상태가 변경되면 화면에 최신 상태를 반영한다.
- 삭제되었거나 조회할 수 없는 게시글은 상세 정보를 표시하지 않고 안내한다.
- 매칭 후보의 상태가 변경되어 진행할 수 없으면 안내하고 최신 상태를 반영한다.
- 반환 기록 상세 화면에서 반환 기록을 취소한 경우에도 관련 게시글과 채팅방의 최신 상태를 반영한다.
- 반환 기록 취소 후 반환 기록 목록 및 상세 화면에서 취소된 기록임을 확인할 수 있도록 한다.
- 반환 처리 이후에도 기존 채팅방과 메시지 내역을 유지한다.

### 6.3 권한에 따른 화면 표시

- 본인 게시글 상세 화면에서만 매칭 후보와 게시글 관리 기능을 제공한다.
- 다른 사용자의 게시글 상세 화면에서는 채팅 시작 기능을 제공한다.
- 반환 완료 처리와 반환 기록 취소 기능은 각각 해당 기능을 이용할 수 있는 사용자에게 제공한다.
- 화면에서 버튼을 숨기거나 비활성화하는 것은 사용자 경험을 위한 처리이며, 실제 권한 검증은 서버에서 수행한다.

권한 조건과 상태 변경에 관한 상세 정책은 [PRD](PRD.md)를 따른다.

## 7. 공통 예외 처리

모든 화면에 적용되는 로딩, 데이터 없음, 요청 실패 및 권한 오류는 다음 기준을 따른다. 화면별로 별도의 동작이 필요한 경우에는 5장에서 추가로 정의한다.

| 상황 | 화면 동작 |
|---|---|
| 최초 데이터 조회 중 | 로딩 표시 |
| 목록에 데이터가 없음 | 빈 목록 안내 및 가능한 다음 행동 표시 |
| 검색 결과가 없음 | 조건에 맞는 결과가 없다는 안내 |
| 최근 검색어가 없음 | 최근 검색어 영역에 저장된 검색어가 없다는 안내 |
| 서버 요청 실패 | 오류 안내 및 재시도 제공 |
| 필수 입력값 누락 | 해당 입력 항목에 오류 표시 |
| 이미지 업로드 또는 메시지 전송 실패 | 실패 안내 및 재시도 제공 |
| 인증 만료 또는 인증 정보 무효 | 인증 정보를 정리하고 카카오 로그인 화면으로 안내 |
| 권한이 없는 기능에 접근 | 접근을 제한하고 안내 |
| 게시글이 삭제되었거나 조회 불가 | 조회 불가 안내 및 가능한 경우 이전 화면으로 복귀 |
| 매칭 후보의 상태가 변경됨 | 최신 상태 확인 후 진행 제한 안내 |
| 반환 완료 또는 취소 처리 실패 | 최신 상태를 반영하고 결과 안내 |
| 반환 취소 기한 만료 | 취소 불가 안내 |
| 푸시 알림 전송 실패 | 메시지 내역은 유지하고 알림 전송 실패와 관련된 처리를 분리 |

오류가 발생하면 사용자에게 이해할 수 있는 안내를 제공한다. 서버 오류 메시지, 인증 정보 및 민감한 시스템 정보를 그대로 노출하지 않는다.

## 8. 미결정 사항

아래 항목은 아직 구체적인 UI 동작이나 표시 방식이 확정되지 않은 사항이다.

- 닉네임 최초 설정 화면의 구성
- 빈 목록 및 오류 화면의 구체적인 문구와 시각적 스타일
- 매칭 추천 근거를 표시하는 구체적인 UI 형태
- 반환 완료 및 반환 기록 취소 시 확인 절차의 구체적인 UI
- 회원탈퇴 후 보존되는 데이터의 표시 정보 및 접근 UI
